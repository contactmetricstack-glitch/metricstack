How this calculator works

Large language model APIs almost all sell usage the same way: you pay for the tokens you send (input) and the tokens the model writes (output). A token is a slice of text, often a short word or part of a word. As a rough rule of thumb, 1,000 English tokens is a little under 750 words, but code, tables and non-English text can land higher or lower. Providers publish a list price in US dollars per million tokens, and your bill is simply volume times that rate.

The calculator takes three volume numbers — input tokens per request, output tokens per request, and how many requests you expect in the period — and multiplies them by each model’s standard-tier list price. If you know that a chunk of the prompt will hit a prompt cache (a system prompt, a retrieved document, or earlier turns that the vendor can reuse), you can set a cached input share. Cached tokens are billed at the vendor’s cached-input rate, which is usually a small fraction of the fresh-input rate. The comparison table then sorts the models with a public list price from cheapest to most expensive for that exact workload.

That last point matters more than a headline “cheapest model” chart. Output is usually several times more expensive than input. A short-answer classifier can look cheap on a flagship model, while a long-form agent that writes thousands of tokens per turn can make a mid-tier model the better buy. The presets are starting points, not benchmarks: a chatbot turn, a retrieval-augmented answer with a long prompt, and an agent loop with both a heavy prompt and a long reply.

The formula

For one request:

cost = ((input × (1 − cacheShare)) / 1,000,000) × inputPrice
+ ((input × cacheShare) / 1,000,000) × cachedPrice
+ (output / 1,000,000) × outputPrice

Total cost is that figure times the number of requests. If you leave the cache share at zero, the middle term drops out and you are paying the full input rate on every token you send. Custom rates, if you type them, replace the list prices for the comparison so you can model a negotiated discount or a quote you already have.

Worked example

Suppose you run a support chatbot: 1,500 input tokens and 400 output tokens, 10,000 requests in a month, and 40% of the input hits a cache.

On Claude Sonnet 5.5 the official rates (checked 14 November 2026) are $2.00 per million input tokens, $0.10 cached, and $10.00 per million output tokens.

  • Uncached input: 1,500 × 0.60 = 900 tokens → 900 / 1,000,000 × $2.00 = $0.0018
  • Cached input: 1,500 × 0.40 = 600 tokens → 600 / 1,000,000 × $0.10 = $0.00006
  • Output: 400 / 1,000,000 × $10.00 = $0.0040
  • Per request: $0.00586. Times 10,000 requests: $58.60 for the month.

The same workload on GPT-6 Luna at $0.10 / $0.50 (cached $0.01) comes to about $2.96, and on DeepSeek Flash at off-peak rates ($0.15 / $0.60, cached $0.003) it comes to about $3.77. The gap is the point of the table: once you know your shape of traffic, the “right” model is a cost and quality decision, not a brand default.

What the list prices include — and what they do not

All figures in the table are standard-tier, first-party list prices in USD per million tokens, verified on 14 November 2026. OpenAI prices come from the official API pricing page (GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra and GPT-6 Luna use the short-context band of 272,000 input tokens or fewer; longer prompts cost more). Anthropic prices come from the Claude platform pricing page (Fable 5.2, Opus 5.5, Sonnet 5.5, and both Haiku 5.5 prompt-length bands). Google prices come from the Gemini Developer API pricing page; Gemini 4 Carbon and Argon are on an introductory $2 / $10 rate through 30 November 2026, and Gemini 3.8 Flash is $0.75 / $3.75 through 31 December 2026. Mistral prices come from the official API pricing docs for Large 4, Small 4 and Codestral. DeepSeek prices come from the official Models & Pricing page and are split into peak and off-peak; peak hours are 01:00–04:00 and 06:00–10:00 UTC, Monday to Friday, excluding Chinese public holidays, and off-peak is half the peak rate. Groq prices for GPT-OSS 120B and 20B come from the GroqCloud model catalogue.

Meta’s Llama 3.3 70B and Llama 3.1 8B Instant are still listed on Groq, but only as Enterprise models with “Contact Sales” pricing. This calculator does not invent a number for them. If you have a quote, type it into the custom rate fields. Public GPT-OSS models on Groq are included at the published $0.15 / $0.60 and $0.075 / $0.30 rates.

The table also leaves out several real costs that can matter in production: batch discounts (often 50%), OpenAI and Anthropic fast or priority modes, Google grounding or search tools, DeepSeek web-search add-ons, image or audio tokens, and data-residency uplifts. If your workload uses those features, treat this page as a baseline and add the extra line items from the vendor’s page.

FAQ

How is LLM API cost calculated?

Providers bill in US dollars per million tokens. Cost equals uncached input tokens times the input rate, plus cached input tokens times the cached rate, plus output tokens times the output rate, then multiplied by the number of requests.

When were these prices checked?

List prices were checked on 14 November 2026 against official provider pages from OpenAI, Anthropic, Google, Mistral, Groq and DeepSeek. The date is shown above the table so you can see how fresh the figures are.

Why do some Meta / Groq models have no price?

On GroqCloud, Llama 3.3 70B and Llama 3.1 8B Instant are listed as Enterprise models with contact-sales pricing. The calculator does not invent a rate. You can enter a custom per-million price if you have a quote.

Does this include batch, fast mode or long-context uplifts?

No. The table uses standard-tier list prices for ordinary short-context calls. Batch discounts, fast or priority modes, and long-context multipliers are described in the notes and should be confirmed on the provider page before you budget.
